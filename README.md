Independent test repository merged from the newer `nol3-hubs/test` project while retaining Test2's extension-version validation and GitHub Actions workflows.

## Included
- BADOC Hub dashboard v104
- Chrome extension v1.5.0, including Downloaded Data display in the POD/POOH Checker
- Firefox extension v69.5.8
- First Mile XLSX-to-CSV support
- On-demand Pickup Info lookup from the signed-in SPX tab, including pickup attempts, geofence, remarks, photos, and seller signature

- One-request combined SPX export for Delivering, Delivered, and OnHold

## Extension version validation
The dashboard checks the installed extension package version separately from the bridge protocol version.

Minimum versions:
- Chrome: `1.4.9`
- Firefox: `69.5.7`

Both extension bridge scripts report their package version during the handshake. Missing or older package versions are rejected by the dashboard. The built-in Chrome installer package is generated from the current Chrome source package. Firefox XPI packages are generated by the repository workflow from `extension-firefox/`.

## Pickup test mode — Orders only
- The main Pickup results use the Pickup Orders export as their only source.
- The only automatic row filter is ETA = today's Philippine calendar date. All order statuses are included, with one result row per Pickup Order.
- Status is read directly from `Status(pickup order)`; `Canceled` / `canceled` is displayed as **Cancelled**.
- Assigned Rider is read directly from the order's `Pickup Driver` field.
- Pickup Tasks are not joined to orders and cannot change the main result's status, rider, or eligibility. Task-only rows and the unmatched-task panel are not part of this test.
- The **Sync Pickup Orders** button requests the Pickup Orders export only. Previously saved Pickup Tasks data and its separate raw-copy control remain available, but it is not used by the main Pickup results.
- Search is a view/search control only; it does not introduce an additional data eligibility rule. The status dropdown is hidden so every ETA-today order status remains visible.
- The combined CSV uses the visible Orders-only results. **Copy for Sheet** uses the same visible orders, while continuing to exclude an order already recorded as canceled/disabled in the previous Philippine day's first-sync Orders baseline. Canceled values are normalized to **Cancelled** in the sheet.
- Pickup Orders exports all statuses and all bulky types, limited by the SPX export's Created Time range. The main result then filters that export by ETA only.
- The first successful Pickup Orders export of each Philippine calendar day establishes the Orders baseline. Each Order ID keeps its first-seen status for that day; newly appearing IDs are appended without overwriting existing entries. Baselines are kept locally and in shared cloud storage.
- Each Order Number retains its on-demand **Pickup Info** action. It reads the authenticated SPX `pickup_info` endpoint and displays pickup status/times, attempt history, task/rider, geofence result, remarks, seller signature, and available photo links. It requires an open, signed-in SPX tab and does not bulk-fetch or cache order details.
