## Extension version validation
The dashboard checks the installed extension package version separately from the bridge protocol version.

Minimum versions:
- Chrome: `1.4.9`
- Firefox: `69.5.7`

Both extension bridge scripts report their package version during the handshake. Missing or older package versions are rejected by the dashboard. The built-in Chrome installer package is generated from the current Chrome source package. Firefox XPI packages are generated by the repository workflow from `extension-firefox/`.

## Pickup test mode — Orders-led with task driver lookup
- The main Pickup results use Pickup Orders as the source for one row per order, ETA eligibility, order status, and order details.
- The only automatic row eligibility filter is ETA = today's Philippine calendar date. All order statuses are included.
- Status is read directly from `Status(pickup order)`; `Canceled` / `canceled` / `disabled` is displayed as **Cancelled**.
- Assigned Rider is read from the `Driver Name` field in Pickup Tasks. Orders and Tasks are matched by normalized Pickup Point ID. When multiple task records share a pickup point, the latest task by Create Time supplies the driver name.
- Pickup Task status is ignored. It cannot change an order's status, remove a row, add a task-only row, or decide ETA eligibility. No other Pickup Task fields are used for the main result.
- The **Sync Pickup Orders + Tasks** button requests Pickup Orders first and Pickup Tasks second, so the latest driver lookup is available. If Tasks are unavailable, ETA-today orders still appear and Assigned Rider shows **Unassigned**.
- Search is a view/search control only; it does not introduce an additional data eligibility rule. The status dropdown is hidden so every ETA-today order status remains visible.
- The combined CSV and **Copy for Sheet** use the same visible Orders-led results. Copy for Sheet continues to exclude an order already recorded as canceled/disabled in the previous Philippine day's first-sync Orders baseline. Canceled values are normalized to **Cancelled** in the sheet.
- Pickup Orders exports all statuses and all bulky types, limited by the SPX export's Created Time range. The main result then filters that export by ETA only.
- The first successful Pickup Orders and Pickup Tasks exports of each Philippine calendar day establish their respective baselines. Each Order ID / Pickup Task Number keeps its first-seen status for that day; newly appearing IDs are appended without overwriting existing entries. Baselines are kept locally and in shared cloud storage.
- Each Order Number retains its on-demand **Pickup Info** action. It reads the authenticated SPX `pickup_info` endpoint and displays pickup status/times, attempt history, task/rider, geofence result, remarks, seller signature, and available photo links. It requires an open, signed-in SPX tab and does not bulk-fetch or cache order details.
